## استیج ۱۸.۲

### هدف
اضافه کردن اکشن‌های **لغو (Revoke)** و **چرخش توکن (Rotate)** برای دستگاه‌ها از طریق منوی long-press، با تأیید و رفرش امن لیست.

### خلاصه تغییرات

| موضوع | توضیح |
|--------|--------|
| **کنترلر** | متدهای `revokeDevice(deviceId)` و `rotateDeviceToken(deviceId)`؛ هر دو بعد از موفقیت `loadDevices()` را صدا می‌زنند. فلگ `isActionInProgress` و try/finally برای جلوگیری از اجرای هم‌زمان. امکان تزریق `DevicesRepository` و `testUserId` برای تست. |
| **رابط کاربری** | Long-press روی کارت دستگاه → bottom sheet با گزینه‌های: Revoke، Rotate token، Copy device ID. برای Revoke و Rotate دیالوگ تأیید نمایش داده می‌شود. موفقیت/خطا با SnackBar؛ آیکون سه‌نقطه (more_vert) روی کارت. |
| **تست‌ها** | `devices_controller_actions_test.dart` با FakeDevicesRepository؛ بررسی می‌کند بعد از revoke/rotate موفق، `loadDevices` فراخوانی شود. |

### فایل‌های تغییر یافته / اضافه‌شده

- `lib/features/devices/logic/devices_controller.dart` — تزریق repo و testUserId؛ `revokeDevice`، `rotateDeviceToken`؛ `isActionInProgress`
- `lib/features/devices/presentation/pages/devices_page.dart` — منوی long-press، دیالوگ تأیید، SnackBar، آیکون more_vert
- `test/devices_controller_actions_test.dart` — تست اکشن‌ها با ریپوی فیک

### محدودیت‌های شناخته‌شده

- در حین revoke/rotate روی کارت loading جداگانه نشان داده نمی‌شود؛ فقط دکمه Register غیرفعال می‌شود.
- کپی device ID فقط در کلیپ‌بورد ذخیره می‌شود و بازخورد بصری آن SnackBar است.

## استیج ۱۹.۱

### هدف
پیاده‌سازی **لایه داده سبک زندگی** (DTOها + ریپوزیتوری) با پارس تایپ‌شده و تست، بدون وابستگی جدید.

### خلاصه تغییرات

| موضوع | توضیح |
|--------|--------|
| **DTOها** | `LifestyleDataCreate`: فیلدهای user_id، sleep_hours، steps، calories، stress_level (اختیاری) برای POST /lifestyle/update. `LifestyleContextResponse`: پارس پاسخ GET /lifestyle/context (شیء یا null). |
| **ریپوزیتوری** | `LifestyleRepository`: متدهای `fetchContext(userId)` و `updateLifestyle(LifestyleDataCreate)`؛ خروجی هر دو `ApiResponse<Map<String, dynamic>?>`. |
| **دیباگ (اختیاری)** | `smokeLifestyleUpdate()` و `smokeLifestyleContext()` در `lib/core/debug/smoke_lifestyle.dart`؛ فقط با فراخوانی صریح اجرا می‌شوند. |
| **تست‌ها** | `lifestyle_dto_test.dart`: toJson برای LifestyleDataCreate؛ fromJson و fromApiData برای LifestyleContextResponse. |

### فایل‌های تغییر یافته / اضافه‌شده

- `lib/data/dto/lifestyle_data_create.dart` — DTO درخواست به‌روزرسانی
- `lib/data/dto/lifestyle_context_response.dart` — پارس پاسخ context
- `lib/data/repositories/lifestyle_repository.dart` — fetchContext، updateLifestyle
- `lib/core/debug/smoke_lifestyle.dart` — توابع smoke برای تست دستی
- `test/lifestyle_dto_test.dart` — تست DTOها

## استیج ۱۹.۲

### هدف
اضافه کردن **صفحه سبک زندگی** با نمایش خلاصه context، فرم به‌روزرسانی دستی (خواب، قدم، کالری، استرس)، و پشتیبانی RTL.

### خلاصه تغییرات

| موضوع | توضیح |
|--------|--------|
| **کنترلر** | `LifestyleController`: متدهای `loadContext()` و `submitUpdate(sleepHours, steps, calories, stressLevel)`؛ state شامل isLoading، isSubmitting، contextMap، errorMessage. |
| **رابط کاربری** | (۱) بخش Context: نمایش فیلدهای برگشتی از سرور یا placeholder در صورت نبود داده. (۲) فرم Update: خواب (۰–۲۴)، قدم (۰–۱۰۰۰۰۰)، کالری (۰–۲۰۰۰۰)، سطح استرس (۰–۱۰). (۳) دکمه Submit با حالت loading؛ SnackBar موفقیت/خطا. مقادیر عددی LTR؛ صفحه برای fa/ar با Directionality.rtl. |
| **ناوبری** | منوی overflow (آیکون more_vert) در هدر چت با آیتم «Lifestyle» تا هدر شلوغ نشود. |
| **اعتبارسنجی** | توابع خالص در `lifestyle_validation.dart` برای بازه‌ها؛ تست در `lifestyle_validation_test.dart`. |

### فایل‌های تغییر یافته / اضافه‌شده

- `lib/features/lifestyle/logic/lifestyle_validation.dart` — اعتبارسنجی بازه‌ها (خواب، قدم، کالری، استرس)
- `lib/features/lifestyle/logic/lifestyle_controller.dart` — loadContext، submitUpdate
- `lib/features/lifestyle/presentation/pages/lifestyle_page.dart` — صفحه Context + فرم Update
- `lib/features/chat/presentation/pages/chat_page.dart` — PopupMenuButton با آیتم Lifestyle
- `test/lifestyle_validation_test.dart` — تست اعتبارسنجی بازه‌ها
